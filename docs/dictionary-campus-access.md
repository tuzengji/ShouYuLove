# 词典校园网访问与反爬保护

2026-10-17 晚间，一批同学在教室连接北大校园网访问词典。入口原来按 IP 限制 24 个并发请求；HTTP/2 中每个在处理的资源请求都计数，多位同学因此共用这 24 个名额。当晚确认有 45 次词典 429 来自这条规则。499 表示客户端提前断开，旧日志缺少请求耗时，不能把全部 499 归为同一个原因。

这次只调整阿里云公网 `/dict/` 的入口策略，源码在本仓库 `deploy/dictionary_guard/`。CLab、阿里云备用词典、报告服务、业务数据库和内容权限策略继续由词典项目维护。其他项目仍使用各自原有配置；词典不再消耗 SignTrace 的 `syl_req`、`syl_conn` 名额。

## 当前规则

| 请求类型 | 规则 |
| --- | --- |
| 普通页面、图片、视频 | 每个已验证会话 64 并发、10 请求/秒，允许额外 120 个突发请求 |
| CSS、JS、`/dict/static/` 图标 | 不要求会话，不占普通会话配额；保留宽松 IP 与项目总量兜底，缓存沿用原响应 |
| 登录、AI 查询启动、管理员评分 | 独立的每会话 2 并发、1 请求/秒、突发 5；同 IP 10 请求/秒、突发 120；这些入口合计最多 128 并发 |
| 同一校园网出口 | 词典独立的 4,096 并发、1,000 请求/秒、突发 12,000；词典项目总并发最多 8,192 |
| 新会话签发 | 同 IP 允许 300 个初始名额，每秒补充 2 个；用尽时仅限制继续签发，既有有效会话仍可访问 |
| 批量遍历 | 每会话每 10 分钟最多访问 1,200 个不同的词条或内容资源键；重复查看已访问资源不增加覆盖数，正常速率限制仍适用 |

会话在首次文档导航时签发，使用随机 128 位标识、24 小时有效期和服务器密钥签名。Cookie 为 HttpOnly、SameSite=Lax，HTTPS 下带 Secure，范围仅 `/dict/`。Nginx 用 `secure_link` 在计数前验证签名和有效期；应用入口再次验证，伪造或重复 Cookie 不能换取新配额。会话不绑定 IP 或浏览器标识，多人使用相同浏览器和校园出口也能分别计数。清除 Cookie 后只在文档导航中重新签发；直接抓取图片不能不断取得新身份。

限流返回 429，并提供 `Retry-After`。内容权限拒绝继续返回 403。视频仍先检查原来的内容权限，再由本机文件或 CLab 回源提供，Range 分段请求保持。报告登录、管理员授权、动作查询的应用内每日额度都沿用原实现；本次不替应用开启或关闭额度。

这些规则限制突发、持续遍历和频繁换会话，不把签名 Cookie 当作真人证明。低速程序或分散出口仍可能访问公开内容。共享出口的宽松兜底也有上限，不能无限放大。

## 验证

先在仅监听回环地址的独立 Nginx 运行测试，正式词典不承受模拟压力。测试沿用线上 Nginx 1.28.3、自动 worker、每 worker 768 个连接、HTTP/2 每连接 32 个流；整个测试组限制为 1 核 CPU、768 MiB 内存。模拟客户端使用同一 IP、相同 User-Agent，各自通过服务端签发会话。

| 同时进入的人数 | 页面、翻页与资源请求 | 成功 | 429 / 5xx |
| --- | ---: | ---: | ---: |
| 30 | 2,130 | 2,130 | 0 |
| 50 | 3,550 | 3,550 | 0 |
| 100 | 7,100 | 7,100 | 0 |

旧规则对照组的 96 次并发中有 72 次返回 429。新规则下，同一会话的 96 次并发放行 64 次、限制 32 次；独立会话仍能访问。单会话超速、伪造 Cookie、频繁领取新会话和低于速率阈值的持续遍历也得到限制。私有视频拒绝、本地与回源视频、Range、无 Cookie 的公共样式、其他项目配额隔离均通过。另模拟 100 个独立会话同时提交查询启动请求，入口全部通过；该测试使用模拟后端，没有调用付费模型。

结构化结果见 [测试记录](evidence/dictionary-nat-20261017.json)。本测试证明请求配额隔离，未测量校园 Wi-Fi、5 Mbps 公网出口或 CLab 实际计算容量。测试中的毫秒数是隔离环境耗时，不能当作用户实际加载速度。

```sh
node --test tests/dictionary_guard.test.mjs
# Linux 隔离验证；需 Nginx、Node.js、Python、OpenSSL，使用 18991/18992 回环端口。
sudo python3 tests/dictionary_nginx_lab.py
```

## 运维和回滚

`shouyulove-dict-guard.service` 使用 Node.js 标准库，仅监听 Unix socket，内存上限 256 MiB、CPU 上限一核。会话签发计数和遍历集合只在内存保存，按窗口清理并限制总大小；重启会清空这部分短期计数。会话签名密钥独立保存在 `/var/lib/shouyulove-dict-guard/signing-key`，只允许 root 读取，通过 systemd credential 交给服务。Nginx 签名片段 `/etc/shouyulove/dict-guard-signing.conf` 同为 root 0600；两处必须使用同一密钥。生成的密钥和片段不得上传 Git，也不要把完整 `nginx -T` 输出公开。

服务代码使用 `/opt/shouyulove-dict-guard/releases/` 和 `current` 链接。入口鉴权服务不可用时请求会失败，不会绕过反爬；因此先启动并检查服务，再启用 Nginx 入口。故障检查先看 `systemctl status shouyulove-dict-guard` 和服务日志，再检查 socket、密钥一致性及配置。

`/var/log/shouyulove-private/requests.jsonl` 新增请求、上游连接与响应耗时、限流结果和守卫拒绝原因。该目录为 root 0700、文件 0600，每日轮转，保留 14 份；不记录 IP、Cookie、查询词和浏览器标识。既有 combined 日志、访问统计格式及报告采集继续保留。

本次配置与服务基线、原配置备份、发布回执保存在 `/var/backups/shouyulove-maintenance/dict-campus-20261017/`。维护时持有 `/run/lock/nginx-deploy.lock`，先核对现场哈希，只修改词典区块，不覆盖其他人新增的路由或当前主备 upstream 模式。完成 `nginx -t` 后平滑 reload；其他项目不重启。

需要回滚时，按备份中的文件清单恢复原站点，撤下本次新增的 `conf.d` 定义和诊断格式，再检查配置并 reload。旧 worker 退出前保留守卫服务，避免其在途请求失去鉴权服务。签名密钥、业务库、统计库和旧回滚包不删除。主站静态运行白名单未变化，无需切换静态版本。
